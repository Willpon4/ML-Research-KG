## What This Course Is

CS 497 is a 15-week upper-division computer science course at James Madison University covering the full lifecycle of knowledge graph engineering — from data modeling and schema design through querying, quality assessment, machine learning integration, and deployment. The course is project-based, meaning the majority of the grade comes from a single capstone project that builds progressively across three milestones.

The course assumes familiarity with Python, basic data structures, and some exposure to databases. No prior knowledge of RDF, SPARQL, or graph theory is required.

---

## Course Structure

The course runs 15 weeks and is divided into four broad phases, each building directly on the last.

### Phase 1: Foundations (Weeks 1-6)

- **Weeks 1-2:** Introduction to knowledge graphs. What they are, why they exist, and how they differ from relational databases and property graphs. Overview of RDF (Resource Description Framework) as the core data model: triples, URIs, literals, named graphs.
- **Week 3:** Schema design using RDFS and OWL. Defining classes, properties, domain/range constraints, and class hierarchies. Introduction to ontology engineering principles.
- **Week 4:** SPARQL, the query language for RDF graphs. SELECT, CONSTRUCT, ASK, and DESCRIBE queries. Filters, aggregations, OPTIONAL clauses, UNION, and subqueries.
- **Week 5:** Graph analytics. Centrality measures, shortest paths, clustering, and how graph structure reveals patterns that tabular data cannot.
- **Week 6:** Ontology engineering in depth. Reasoning, inference, OWL axioms, and how to design ontologies that are both expressive and practical.
- **MILESTONE 1 DUE (Week 6):** Complete schema design: 8+ classes, 16+ properties, class hierarchy diagram, 20-30 sample entities, 4-page project report.

### Phase 2: Knowledge Extraction (Weeks 7-9)

- **Week 7:** Text and markup extraction. Pulling structured information from unstructured sources: APIs, web scraping, XML/JSON parsing, regular expressions.
- **Week 8:** NLP techniques for knowledge extraction. Named entity recognition, relation extraction, coreference resolution. How to turn natural language into triples.
- **Week 9:** Knowledge graph quality assessment. Completeness, accuracy, consistency, and provenance. Validation rules and how to track data lineage using named graphs.

### Phase 3: Machine Learning on Knowledge Graphs (Weeks 10-12)

- **Week 10:** Graph embeddings. TransE, RotatE, ComplEx: representing entities and relationships as vectors in continuous space. Evaluation using Mean Reciprocal Rank (MRR) and Hits@K.
- **Week 11:** Link prediction. Using trained embeddings to predict missing or future relationships. How to split data, evaluate predictions, and interpret results.
- **Week 12:** Symbolic learning and reasoning. Rule mining, path-based reasoning, combining neural and symbolic approaches.

### Phase 4: Final System (Weeks 13-15)

- **Week 13:** KGs in practice. Publishing, SPARQL endpoints, AllegroGraph triplestore, real-world KG applications.
- **MILESTONE 2 DUE (Week 13):** Working KG: 1,000+ triples, extraction pipeline from all three sources, 10 SPARQL queries covering all use cases, graph embeddings trained and visualized (t-SNE/PCA), link prediction evaluated with MRR and Hits@K.
- **Week 14:** Capstone development. Refining the system, building the user interface, preparing the presentation.
- **Week 15:** Final presentations in class.
- **MILESTONE 3 DUE (Week 15):** Complete system: 1,500-2,000 triples, user interface (Jupyter notebook or web app), working paper recommendation engine, 30-40 slide presentation, 10-15 page final report, public GitHub repository.

## The 6 Use Cases

All system components are designed around these six core questions the KG must be able to answer:

1. **Paper Recommendation:** Based on papers I have read, what should I read next? Method: citation patterns and topic similarity.
2. **Emerging Trend Detection:** What topics are getting attention right now? Method: papers with rapidly increasing citations and new keyword combinations.
3. **Foundational Paper Discovery:** What are the most important papers on transformers? Method: citation network analysis to find highly-cited landmark works.
4. **Expert Discovery:** Who are the leading researchers in graph neural networks? Method: rank authors by publication count and citation impact in a specific area.
5. **Research Timeline Tracking:** How has deep learning evolved over time? Method: trace citation chains to understand how ideas developed year over year.
6. **Collaboration Discovery:** Who works together on similar topics? Method: map co-authorship networks across institutions.

---

## Success Criteria

**Schema:** Clear class hierarchy, proper domain/range constraints, all 6 use cases expressible through the schema design.

**Data:** 1,500+ validated triples, no orphaned entities, provenance tracked via named graphs, >90% completeness for critical properties, >95% accuracy.

**Queries:** All 6 use cases functional via SPARQL, queries execute in under 5 seconds, at least 10 queries demonstrating different patterns.

**ML:** Meaningful entity clustering visible in t-SNE/PCA, MRR > 0.3 for link prediction, Hits@10 > 0.5, recommendations are sensible and interpretable.

**Documentation:** Complete README, example queries, reproducible results, clear explanation of design decisions in the report.

## Final Deliverables (Milestone 3)

**1. Complete Knowledge Graph System**
Refined KG with 1,500-2,000 high-quality triples, all 6 use cases functional end-to-end.

**2. User Interface**
A Jupyter notebook with interactive queries and visualizations, or a simple web app for paper search and recommendations. Must demonstrate all use cases to a non-technical audience.

**3. Final Presentation**
30-40 slides prepared, approximately 20 presented in class. Must cover: project overview, schema design rationale, data pipeline, quality assessment, ML techniques and evaluation, live demo, lessons learned, and future work.

**4. Final Technical Report**
10-15 pages. Sections: Introduction and motivation, related work (other research KGs), system design and architecture, implementation details, ML techniques and evaluation, results and discussion, conclusions and future work, appendix (SPARQL queries, code samples).

**5. Public GitHub Repository**
Clean well-documented code, complete README with setup instructions, schema files (.ttl), example SPARQL queries, ML pipeline code, sample data or instructions to generate it, documentation folder.
